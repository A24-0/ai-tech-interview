## 2 Назначение и цели создания системы

### 2.1 Назначение системы

Система предназначена для самостоятельной подготовки кандидатов к техническим собеседованиям. Пользователь проходит текстовое интервью с интервьюером на основе большой языковой модели (LLM), решает практическую задачу на Python во встроенном редакторе с выполнением кода в изолированной среде и получает отчёт с объяснением: что верно, где ошибка и что улучшить. Результаты сохраняются в истории и формируют прогресс по темам.

### 2.2 Цели создания системы

*Таблица 2 — Цели и критерии их достижения*

| Цель | Критерий достижения |
|---|---|
| Дать возможность пройти полное техническое интервью (теория и практическая задача) без живого интервьюера | Сценарий «вход → интервью → задача → отчёт → история» проходит без участия разработчиков |
| Сделать оценку объяснимой и воспроизводимой | Каждое замечание отчёта ссылается на сообщение или строку кода; оценка совпадает с эталонной (отклонение не более 1 балла из 10) не менее чем в 80 % случаев |
| Показывать прогресс подготовки | История интервью и прогресс по темам и уровням обновляются после каждого отчёта |
| Обеспечить безопасность при выполнении произвольного кода | Код пользователя выполняется без доступа к сети, с ограничением памяти, процессора, числа процессов и времени |

## 3 Характеристика объекта автоматизации

Объектом автоматизации является процесс подготовки кандидатов к техническим собеседованиям в сфере разработки программного обеспечения. В настоящее время он выполняется разрозненно: платформы задач с автоматической проверкой оценивают только результат работы кода и не ведут диалог; списки типовых вопросов не проверяют понимание; пробные собеседования с живым интервьюером требуют времени другого человека и часто платные; универсальные чат-боты на основе языковой модели не выполняют код на наборе тестов, не придерживаются банка вопросов и уровня, а их оценки от раза к разу различаются.

*Таблица 3 — Пользователи системы*

| Пользователь | Роль в процессе | Потребность |
|---|---|---|
| Кандидат (студент, начинающий разработчик) | Проходит тренировочное интервью, решает задачи | Реалистичная практика, объяснимая обратная связь, отслеживание прогресса |
| Администратор контента (преподаватель, наставник) | Наполняет банк вопросов, задач и критериев оценки | Удобное редактирование контента, контроль качества вопросов |

Роль интервьюера в системе выполняет языковая модель под управлением сервера.

### 4.3 Требования к видам обеспечения

**Информационное обеспечение.** Данные хранятся в СУБД PostgreSQL 16. Логическая модель включает сущности: users, refresh_tokens, topics, questions, code_tasks, criteria, interview_sessions, messages, code_runs, reports, user_topic_progress, audit_log. Схема приводится к третьей нормальной форме. Для идентификаторов, передаваемых клиенту, используется тип uuid. Вопросы банка не удаляются, а деактивируются; критерии оценки версионируются. Частичный уникальный индекс обеспечивает правило «одна активная сессия на пользователя», уникальный индекс по client_message_id — отсутствие дубликатов при повторной отправке ответа.
