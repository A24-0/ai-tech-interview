# План тестирования

## Цели
Показать, что MVP «AI Tech Interview» проходит сценарий вход → интервью → код → разбор → отчёт, не теряет данные и не позволяет коду кандидата выйти за границы песочницы.

## Объекты
- AI-слой: провайдер модели, интервьюер, разбор кода.
- Песочница: `runner.py`, `DockerSandbox`.
- API: интервью, запуски кода, права доступа.
- Клиенты: Web и Windows (Flutter).

## Уровни и инструменты
| Уровень | Что проверяем | Инструмент |
|---|---|---|
| Модульные | логика интервьюера, разбор ответа модели, повторы, парсинг вывода runner | pytest, подмена HTTP через `httpx.MockTransport`, `FakeChatProvider` |
| Песочница | лимиты времени, памяти, процессов, сети, файловой системы, вывода | pytest с настоящим Docker (`sandbox/tests/evil`) |
| Нагрузка | 20 параллельных запусков кода | `sandbox/tests/load` |
| Интеграционные | ответы API, SSE, статусы сессий и запусков | тест-кейсы `docs/tests/interview_cases.md` |
| Качество AI | оценки модели против эталона, повторяемость | `docs/eval/` |
| Регресс | сценарии S1-S3 на стенде | `docs/tests/regression_s1_s3.md` |
| Приёмка | три внешних пользователя без подсказок | протокол прогона |

## Критерии
- Автотесты зелёные в CI на каждом PR (`.github/workflows/sandbox.yml`).
- Все пункты `docs/security.md` закрыты на стенде.
- Регресс без блокирующих дефектов.
- Расхождение оценок AI с эталоном описано и передано разработчику AI-слоя.

## Окружения
Локально (Docker Desktop), CI (GitHub Actions), стенд (VPS, Docker Compose).

## Риски
| Риск | Что делаем |
|---|---|
| Недетерминизм модели | три прогона эталона, сравнение расхождений |
| Недоступность провайдера | тест-кейс IV-08, повторы с задержкой, событие `error` в SSE |
| Побег из песочницы | лимиты ADR-002, автотесты злого кода, `docker-socket-proxy` |
| Нехватка ресурсов стенда | нагрузочный прогон, запись предела в `docs/metrics.md` |

## Что не входит
Тестирование безопасности самой платформы Docker и сервера хостинга.
